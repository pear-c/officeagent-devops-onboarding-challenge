# OfficeAgent 멀티 환경 배포 설계

AWS → NHN(공공 중등급) → 오픈스택(상등급) 마이그레이션

깊이 도메인: **A. 네트워크/보안** · **B. 데이터/스토리지**

<small>2026-06 · 학습용 재작성 · 발표 30분 + Q&A 30분</small>

---

## 표준 시작 질문에 먼저 답합니다

> "깊이 다룬 2개 도메인 중 가장 큰 미해결 위험 1개와 근거는?"

**위험: NHN RDS for PostgreSQL에 무중단 마이그레이션 전용 도구(DMS)가 없다.**

- NHN 공식 docs의 외부 DB 이전 안내는 **`pg_dump`(dump/restore)뿐** *[확인됨, backup-and-restore]*
- 즉 **4h 무손실 다운타임 충족이 DB 용량에 선형 비례** → 용량 미상이면 보장 불가
- (검색에 잡힌 "DB Migration Service"는 **Naver Cloud** 문서였음 — NHN 아님. 혼동 차단이 조사의 핵심)
- **대응**: pg_dump 병렬+사전 증분(1차) / 엔진 레벨 logical replication 수동 구성(2차) — 둘 다 4h 합산·리허설로 검증

---

## 깊이 도메인을 A·B로 좁힌 이유

트래픽이 작다(동시<200, RPS 5/50). **컴퓨트·네트워크 전환 난이도는 낮다.**

진짜 난이도는 셋:
1. **데이터 무손실 4h 이전** → B
2. **LLM API 데이터 주권** → B
3. **상등급 오픈스택 재작성** → A·추상화

→ 5개 도메인을 얕게 훑지 않고 **A 네트워크/보안 + B 데이터/스토리지**에 집중.

---

## 설계 앵커: CSAP 등급이 망분리를 가른다

| 등급 | 망분리 | 배포 환경 |
|------|--------|-----------|
| **상** | 물리 | 퍼블릭 불가 → **오픈스택 온프레미스** |
| **중** | 논리 | **NHN 공공 전용 리전** |
| 하 | 논리 | NHN |

→ **이원화**: AWS(상용 유지) + NHN(중등급 1차) + 오픈스택(상등급 장기)
법적 근거: 개인정보보호법 시행령 **§48의2** (2025-10-31 위험기반 전환)

---

## 의사결정 1 — CSAP 등급 이원화

| | 채택: NHN 중 + 오픈스택 상 | 대안 A: 전부 상등급 | 대안 B: 전부 NHN 중 |
|---|---|---|---|
| 비용·운영 | 균형 | 과잉(일반공공까지 온프레미스) | 최소 |
| 규제 커버 | 전 고객 | 전 고객 | 국방·최고규제 **납품 불가** |
| 추상화 비용 | 발생(감수) | 낮음 | 낮음 |

**근거**: 상=물리망분리라 퍼블릭 불가 → 오픈스택 필수. 중=논리라 NHN 가능.
**리스크**: 처리 정보가 민감 개인정보면 NHN 중등급 부족 → 상등급 강제.

---

## 의사결정 2 — RDS 4h 무손실 이전 (★최대 난제)

| | 1차: pg_dump 병렬 | 2차: logical replication | 대안: AWS DMS |
|---|---|---|---|
| 다운타임 | 용량 비례 | 분 단위 | 분 단위 |
| 단순성 | 높음 | 중(권한 의존) | 낮음(국외 제어) |
| NHN 지원 | **공식(pg_dump)** | wal_level=logical 미확인 | 타깃 동작 미검증 |

**4h 합산(가정 DB≤50GB)**: 덤프 60' + 복원 100' + 무결성 30' + 전환 25' + 버퍼 15' = **≤4:00**
**롤백 트리거**: 무결성(행수+MD5 해시) 불일치 → DNS 원복

---

## 의사결정 3 — LLM API 데이터 주권 (숨은 핵심)

OfficeAgent는 Anthropic/OpenAI를 **국외 호출** → 개인정보 송신 시 **개보법 §28의8(국외 이전)** 적용(동의+고지 5종).

| 등급 | LLM 전략 |
|------|---------|
| 중(NHN) | **PII 마스킹 게이트** + 감사로그 (국외 호출 허용 가능) |
| 상(오픈스택) | **온프레미스 LLM / 국내 모델**(HyperCLOVA X) 강제 |

**트레이드오프**: 마스킹=품질↓ 위험 / 온프레미스=비용·운영↑·주권 완전.
검증: 마스킹 게이트 입력 PII → 출력 `***`(grep 0건).

---

## 의사결정 4 — 멀티 환경 추상화 (포트 + 어댑터)

앱은 "S3"가 아니라 **"오브젝트 포트"**를 호출. 포트 뒤 어댑터가 환경 차이를 흡수.

- S3 호환 API 덕에 **AWS·NHN은 같은 어댑터 공유** → 오픈스택(Swift s3api)만 별도
- 가장 중요한 포트 = **LLM 게이트웨이** — §28의8 정책을 코드 변경 없이 환경별 주입

→ 정식 4영역 분리도: `assets/architecture-layers.drawio`

## NHN-only 종속 — 오픈스택 단계 재작성 (솔직히)

| 영역 | NHN-only | 오픈스택 대안 | 재작성 비용 |
|------|----------|---------------|:----------:|
| 키 관리 | Secure Key Manager | Vault/Barbican | **높음** |
| 관측 | Log&Crash + Monitoring | Prometheus/Grafana/Loki | **높음** |
| 관리형 DB | RDS for PostgreSQL | Trove(미성숙)/PG 직접 | **높음** |
| LB | NHN LB | Octavia(amphora) | 중 |
| 컨테이너·로직 | (종속 없음) | 그대로 | **없음(공통)** |

→ 그래서 키관리·관측·DB를 **포트로 추상화**해 두는 것이 NHN 단계의 투자.

## 검증 산출물 (재현 가능성)

| 시나리오 | 기대 출력(구체값) |
|---------|------------------|
| A-1 네트워크 validate + SG | `Success!` + DB ingress `0.0.0.0/0` **0줄** |
| A-2 망분리 도달성 | 중: 공인망→DB `exit=124` / 상: 외부호출 `000` |
| B-1 DB 이전 무결성 | 행수 diff **0줄** + MD5 해시 일치 |
| B-2 객체 sync | dry-run **0줄** + 객체수·바이트 동일 |
| B-3 LLM 마스킹 | outbound에서 원문 PII `grep` **0건** |

모두 입력·명령·기대출력·**실패판단** 4종 명시.

## 가장 큰 미해결 위험 1~2

1. **NHN RDS 무중단 도구 부재 + DB 용량 미상 → 4h 불확실**
   - 대응: pg_dump 1차 / logical replication 2차 · 검증: 용량 실측 + NHN 문의
2. **LLM 국외 호출 데이터 주권(§28의8) — 마스킹 누락 시 위법**
   - 대응: 등급별 차등 · 검증: 마스킹 게이트 회귀

(보조) **WebFetch 차단으로 1차 자료 원문 미정독** — 신뢰도 *[확인됨/부분확인/미확인]* 표기로 숨기지 않음.

# 부록 — Q&A 5축 대비

## 축 1·2 — 의사결정 근거 / 대안의 단점

- **CSAP 이원화**: 상=물리망분리라 퍼블릭 불가가 결정타. 대안(전부 상등급)은 일반 공공까지 과잉비용.
- **pg_dump 1차**: NHN 공식 지원이라 단순·검증 용이. 단점=다운타임 용량 비례 → 그래서 2차안 병행.
- **내 설계가 깨질 시나리오**: 운영 DB가 수백 GB거나 NHN이 `wal_level=logical`을 막으면 4h 불가 → 점진 이전·읽기전용 기간 협상 필요.
