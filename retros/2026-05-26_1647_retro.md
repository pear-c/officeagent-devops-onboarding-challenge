## 사용자 보강 (메인 Claude 세션, 2026-05-27 추가)

### 1차 호출 무동작 — 근본 원인 추정

claude CLI `--help` 직접 확인 결과:
- `claude [options] [prompt]` 형식, `-p/--print`는 non-interactive 모드.
- `--allowedTools <tools...>` Comma or space-separated **list** (`"Bash(git *) Edit"` 형태가 정상). 본 훅의 호출은 각 도구가 별도 인자로 들어가는 형태였음.

**가설**: 1차 호출의 사일런트 무동작은 `claude -p "$(cat $SKILL_PATH)" --allowedTools 'Bash(command)' 'Read(file_path)' ...` 호출에서 `--allowedTools` 뒤의 두 번째 이후 인자(`'Read(file_path)'` 등)가 **두 번째 prompt로 해석**되어, 결국 prompt 내용이 SKILL이 아닌 단편 문자열들로 합쳐졌을 가능성. 두 번째 호출(채팅 입력 `claude -c -p "..."`)에서는 prompt 인자가 단일 문자열이라 정상 진입.

→ **Try 항목에 추가**: post-commit 훅의 `--allowedTools` 인자를 **단일 공백 분리 문자열**로 묶기. 예:
```bash
claude -p "$(cat $SKILL_PATH)" --allowedTools 'Bash(git *) Read Write Glob Grep' 2>/dev/null
```

(단 이 가설은 1차 jsonl을 메인 세션이 직접 확인하지 않았으므로 100% 단정은 아님 — Day 5 버퍼에 검증 시도 후보.)
