## 프롬프트·시행착오

### 시행착오 1 (Day 3) — NHN docs URL 패턴 redirect

**프롬프트 (요약, 원문 3건)**:
- `WebFetch(docs.nhncloud.com/ko/Network/VPC/ko/overview/)` — Day 1에 성공한 패턴 그대로 재사용
- `WebFetch(docs.nhncloud.com/ko/Storage/Object%20Storage/ko/overview/)`
- `WebFetch(docs.nhncloud.com/ko/nhncloud/ko/public-iam/)`

**AI 응답의 문제**: 3건 연속 302 redirect (`http://www.nhncloud.com/error/CAoNCgYFA`). Day 1과 똑같은 URL 패턴인데 일부 페이지만 작동, 일부는 redirect. NHN docs의 URL 규칙이 균일하지 않음 — 검색 + 발견 사이클이 필요한 상태.

**비판한 부분**: 첫 fetch 실패에 *"URL이 존재하지 않을 수 있다"* 또는 *"NHN docs는 직접 fetch 어렵다"* 같은 적당한 결론으로 넘어가면 1차 자료 부재로 §6 트리거 #4 위반.

**다르게 간 방법**: `WebSearch(allowed_domains=["docs.nhncloud.com"])` + 자연어 키워드 ("NHN Cloud VPC 보안그룹" / "Object Storage S3 API")로 재시도. 검색 결과의 실제 URL 패턴이 다름을 발견:
- VPC console = `/en/Network/VPC/en/console-guide/` (영문)
- OBS S3 = `/zh/Storage/Object%20Storage/zh/s3-api-guide/` (중문 페이지가 가장 풍부)
- IAM = `/ko/quickstarts/ko/iam-accounts/` (`/quickstarts/` 카테고리, 예상한 `/nhncloud/` 아님)

→ **재시도 패턴 자체가 1차 자료 확보의 핵심**. 첫 시도 실패 ≠ 자료 부재.

### 시행착오 2 (Day 3) — 법령 본문 직접 인용 불가

**프롬프트**:
- `WebFetch(law.go.kr/LSW/lsInfoP.do?lsId=011357)` — 개보법 본문 정확 인용

**채택한 점**: AI의 솔직성을 그대로 신뢰. 가짜 조문을 만드는 것보다 *"조문 번호·요건 골조만 박제 + 본문 미접근 솔직히 명시"*가 §6 트리거 #4 회피에 더 안전.

**다르게 간 방법**: `WebSearch(개인정보보호법 §28의8 국외이전)`로 4가지 요건 골조 (① 동의 ② 법령·조약 ③ 보호위원회 인증 ④ 보호 수준 인정 국가) + §28의9 중지 명령 + §39의13 + §75 제재 추출. VALIDATION.md §3 가정·한계 표에 *"법령 본문 직접 인용 미접근 — 조문 번호·요건 골조만 박제"* 명시.

→ **미해결 위험 솔직성 = PRD §6 트리거 #4 회피 + Track C 시그널** 동시 충족.

### 막힘 1 (Day 3) — NHN IAM에 워크로드 자격증명 메커니즘 미명시

NHN IAM docs를 직접 확인했는데 **Instance Profile / Service Role / AssumeRole 같은 워크로드 인증 메커니즘이 명시되어 있지 않음**. AWS의 *"Pod가 자동으로 자기 Role을 가짐"* 패턴이 NHN에선 어떻게 되는지 docs로 확인 불가.

**돌파**: *"NHN docs에 명시 없음 = NHN이 패러다임이 다름"*으로 해석. **Secret manifest + Secure Key Manager 사이드카 또는 init container** 패턴으로 대체. NHN Secure Key Manager의 클라이언트 인증이 IPv4/MAC/인증서 기반인 점 (AWS IAM Role과 다른 패러다임)을 *"근거"* 필드에 박제.

이것이 A-3 의사결정 박스의 핵심 발견. **NHN-only 종속의 솔직한 식별** = 추상화 점수 시그널 (PRD §4 20%). 발표 자료 §8 슬라이드 *"A-3 핵심 발견"*으로 직결.

### 막힘 2 (Day 3) — B-1 4h 다운타임 충족 근거 정량화

### 막힘 3 (Day 3) — B-3 LLM 데이터 주권의 무게

이 박스가 본 과제 가장 무거움. §28의8 4가지 요건 + 미국이 *"보호 수준 인정 국가"* 포함 여부 미확인 + 마스킹 라이브러리 정확도 + HyperCLOVA X 응답 품질 + 온프레미스 옵션까지. 박스 하나에 너무 많이 들어가서 *"잠정 결론"* 한 문장으로 표현이 어려움.

**돌파**: **3단 방어 전략**으로 통합:
1. 마스킹 (필수, 1단계)
2. 감사 로그 100% (필수, 2단계 — §28의9 중지 명령 대응)
3. 국산 모델 비교 (장기 옵션, 3단계)

위 3단계로 정리하니 잠정 결론 한 문장으로 압축 가능. 5개 대안 (호출 차단·동의만·온프레미스·국산·마스킹) + 5개 리스크 + 2개 검증 시나리오 (B-4 마스킹 단위 테스트 + B-5 응답 품질 비교) 연결.

**가장 큰 미해결 위험은 R1**: 미국이 §28의8 ④의 보호 수준 인정 국가인지 — 보호위원회 공시·법무 자문 필요. 운영 단계 검증 항목. **발표 시작 2분 안에 즉답할 카드** — slides.md §2 표준 시작 질문 답으로 직결.

NHN Provider가 `*_v2` 명명 사용 → OpenStack 호환 추정. 그러나 **NHN 매니지드 서비스(RDS·OBS·NKS·Secure Key Manager)는 OpenStack에 없는 NHN 고유 자원**. resource 명 추정 불확실 (`nhncloud_db_*` vs `nhncloud_rds_*` 등).

**돌파**:
1. WebSearch에서 직접 확인된 resource 명만 코드에 박음 (`nhncloud_networking_*_v2`, `nhncloud_compute_instance_v2`, `nhncloud_lb_member_v2`, `nhncloud_keymanager_secret_v1`)
2. RDS·OBS는 placeholder + 주석으로 *"모양만"* 박제 — `database.tf` / `storage.tf` 본문이 거의 다 주석
3. `infra/openstack/README.md`에 *"NHN root가 OpenStack 기반 명명을 그대로 쓰기 때문에 상당 부분 재사용 가능 — 단, 매니지드 서비스 영역은 자체 운영 도구로 대체 필요"* 명시
4. 이 차이 자체가 ARCHITECTURE.md §4 NHN-only 종속 식별의 **코드 입증** = 추상화 점수 시그널 (PRD §4 20%)

## AI 흔적 가시화 (Track C 시그널)

본 회고 자체가 Track C 핵심 산출물. 정리:

### 사용한 도구·프롬프트 패턴
- `WebSearch(allowed_domains=...)` — 1차 자료 URL 발견 (NHN docs URL redirect 우회)
- `WebFetch(direct URL)` — 자료 본문 추출 (재시도 1~3회까지 받아들임)
- `Edit / Write` (의사결정 박스 6요소 templating)
- `Bash(grep "잠정 결론")` — §6 트리거 #3 자동 점검
- `Bash(filter-branch + force-with-lease push)` — Git 계정 분리

### AI 응답을 그대로 받지 않은 결정 (5건)
1. **NHN URL redirect** → AI의 *"URL 미존재"* 결론 거부 + WebSearch 재시도
2. **법령 본문 미접근** → AI의 *"가짜 조문 만들지 않음"* 채택 + 골조만 박제 + *"본문 미접근"* 솔직히 명시
3. **단순 1:1 매핑 회귀 방지** → AI에 단순 본문 요구 대신 6요소 templating + 대안 단점 의무화
4. **Terraform resource 명 추정** → AI의 추정에 의존하지 않고 WebSearch로 확인된 것만 박음 + 나머지는 placeholder + 주석
5. **Retrobot 자동 회고 무동작** → AI의 *"무동작 종료"* 받아들이지 않고 본 수동 회고 작성 (Day 1 retro §사용자 보강 패턴 따름)

### 가장 막힌 지점 + 돌파 1줄 정리
- **NHN URL redirect** → WebSearch 재시도 패턴
- **법령 본문 미접근** → 골조만 박제 + 솔직히 명시
- **NHN IAM 워크로드 자격증명 부재** → 패러다임 다름으로 재해석 + Secret manifest + Secure Key Manager 사이드카
- **B-1 4h 가정 깨질 위험** → sim-4h-budget.sh 정량 + 4가지 fallback 박제
- **B-3 LLM 무게** → 3단 방어 전략으로 통합
- **Terraform CLI 미설치** → skeleton 작성 + Day 5 사용자 실행 위임 + PRD §1.3 활용
- **Terraform resource 명 불확실** → 확인된 것만 박음 + placeholder 주석으로 한계 명시
- **Retrobot 자동 회고 3회 무동작** → 수동 회고 작성 + 워크스페이스 측 fix 별도 분리
